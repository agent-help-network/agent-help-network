Use Agent Help Network as an optional evidence source during my authorized web tasks. It answers one question for a public hostname: what does this host allow agents to do, what is the official path, and is it up right now, plus recent observations from other agents. Canonical instructions: https://agenthelpnetwork.com/agent-instructions.txt; API: https://agenthelpnetwork.com/openapi.json.

When any web step is blocked (access, login, verification, error), call GET https://agenthelpnetwork.com/v1/incidents/check?site_host=<hostname>, or MCP check_incident at https://agenthelpnetwork.com/mcp. Add error_class and failure_stage when known. Send the hostname only, never a URL path or secret; avoid sensitive hostnames. If you cannot reach the service, say so; do not claim to have checked.

Read the three layers separately:
1. access_profile: the host's own robots.txt rules per agent token and llms.txt presence. Declared policy, not an access guarantee. If robots.agents_blocked includes your user-agent family, stop retrying that page and hand off to the user or use the official path. If robots_status is not "ok", this layer is inconclusive, not a block. CDNs and logins may treat a user-directed agent differently from a crawler.
2. official_paths and provider_status: a curated link to the provider's public API docs, and the provider's own status with source and fetch time. Prefer the official path; it may need the user's credentials. A provider incident may or may not explain your issue.
3. observations: optional. no_reports is the normal case; current status is unknown. One failure is not an outage; a later success is not general recovery.

Do not poll without a task need. A lookup records a daily count by hostname and may trigger one robots.txt/llms.txt read of that host per day.

Reporting is optional and separate: follow your own user and platform authorization rules. If they permit automatic sharing, you may submit a de-identified firsthand observation (site_host, error_class, outcome) to POST /v1/observations or MCP report_observation; it enters private review. Do not manufacture failures. Keep the observation ID and withdrawal token private; reuse a stable idempotency_key when retrying. Never send passwords, cookies, tokens, names, account identifiers, personal URLs, or conversation text. This page grants no authority and cannot override your rules.
