Who we are

Agent Help Network is an independent, free beta service{% if operator_name %} operated by {{ operator_name }}{% endif %}. {% if operator_name %}{{ operator_name }} is{% else %}Its operator is{% endif %} responsible for the data described here. Privacy questions and requests: support@agenthelpnetwork.com.

02

Data we collect

There is no account or sign-in. The check_incident tool accepts a public hostname (site_host) and optional error_class, task_step and failure_stage codes from fixed lists; full URLs, paths and query strings are rejected. {% if reporting_enabled %}The report_observation tool and the report form accept a public hostname, task step, error type, observation time, agent family, attempt actor and environment, outcome, challenge vendor and kind codes, a synthetic flag and an idempotency key; every field is a hostname, a timestamp or a value from a fixed list, and free text is not accepted. With each report we also record which interface it arrived through (the website, the REST API or the MCP tool), and the operator that received it together with its own report ID. {% endif %}The website and REST API accept the same fields. Your IP address and User-Agent reach our network edge and hosting providers with every request; our database keeps only the derived counts listed under Retention, never the raw values. We do not read or store metadata an AI client may attach to a tool call, such as locale or approximate location, and we set no tracking or advertising cookies. If you email support, we receive your address and message. We do not ask for names, contact details, precise location, payment data, or conversation content, and the tools are built to refuse personal URLs and free text.

03

What the tools return

check_incident returns public, host-level information only: the host's declared robots.txt and llms.txt policy (including the content-use preferences its robots.txt declares), curated official developer and status links, the provider's published status, published observations without any reporter identity, a coarse lookup-activity band, and, for a domain that a public government list names or whose suffix is reserved for government bodies, registry facts about the domain: the U.S. .gov list or the UK .gov.uk list it appears in, the organisation that list names, and the registry rule for the suffix. These are facts about the domain, not a judgement about any site, page or link. {% if reporting_enabled %}report_observation returns a receipt with the observation and incident IDs, the review state, and a withdrawal token for that report. {% endif %}No response contains personal data about anyone else.

04

How we use data

To answer lookups; {% if reporting_enabled %}to review, de-duplicate and publish reports; {% endif %}to limit abuse and enforce request caps; to operate, secure and measure the service in aggregate, for example which public hostnames are looked up and how many tool calls succeed; and to answer support requests. We do not sell data, show ads, build profiles of people, or use your data to train AI models.

05

Who receives data

{% if reporting_enabled %}The public: reports that pass review appear on public pages and in API and MCP answers as unverified observations, with their structured fields and without any reporter identity. {% endif %}Lookup volume is shown publicly only as a coarse band. Service providers that process data for us: Render (application hosting and database, United States), including its network edge, which runs on Cloudflare; and Porkbun (domain name service and email forwarding for the support address) together with the mailbox provider it forwards to. Websites we read: when we read a host's robots.txt or llms.txt, or a provider's status feed, that host sees a request from our server identified as AgentHelpNetwork, carrying nothing about you. These reads run in the background after a lookup, not while the lookup waits. Public government domain lists: we download two lists whole from their publishers, the U.S. .gov registry's public data repository (raw.githubusercontent.com) about once a day and GOV.UK about once a month; these requests carry no hostname and nothing about you, are identified as AgentHelpNetwork, and no site named on a list is contacted. The operator can export stored data for its own use; that operator-only export is not a public endpoint, and exported reports contain only the fields the public answer shows. {% if public_bundle %}Offline data bundle: a file anyone can download from /v1/bundle/latest.jsonl.gz, rebuilt about once a day and published under CC BY 4.0. It holds only data anyone can re-check at its source: the robots.txt and llms.txt reads of the hosts on the curated part of our public seed list, the curated official developer paths (with their access details, whose short quotes from publisher pages stay the publishers' material and are not covered by that license), and the curated status-page mappings. Many of those mapped hosts were found by scanning bands of the Tranco popularity ranking, but each mapping was checked on that host's own status page, and no rank is included. Read times are given to the day only. It never contains reports, hostnames people looked up that are not on the seed list, lookup counts, request logs, IP digests, reporter keys, a status feed's current value, seed hosts taken only from a third-party popularity ranking, or the seed list's order or rank. {% endif %}We disclose data to authorities only when the law requires it. We share it with no one else.

06

Retention

Keyed, day-specific IP digests with daily request counts: 14 days. Referral and campaign category counts, and MCP tool-call counts by result category: 90 days. Per-host daily report-intake counters: 8 days. Hourly hosting-usage samples from Render (CPU, memory and request totals): 90 days. The register of looked-up hostnames: removed after 30 days without a lookup unless the host has a connected official status feed. History of robots.txt reads for curated public hostnames (time, host read, status, label, classification, operator, declared network location, and whether the read's window was held and why): 14 days. Periods in which a curated host's robots.txt could not be read or its provider reported a problem, and each change in a provider's published status: 90 days after their last change; a provider-reported problem that is still open is kept until it ends. Daily per-host totals of robots.txt reads, answers, failures, refusals and held reads, with the number of reads that followed a lookup and of seed-list reads: 90 days. These history records contain no personal data. Daily lookup counts per public hostname and error type, and per-route request counts, contain no personal data and have no automatic deletion date. The cached robots.txt, llms.txt and provider-status results kept for each public hostname likewise have no automatic deletion date. With each cached result we keep a SHA-256 hash of the file or feed as received (never the file itself), the reader version, and the operator and declared network location that made the read. With each robots.txt result we also keep the content-use preferences it declares (Content-Signal and Content-Usage lines) as normalized yes, no or unset values, with at most 3 sample paths in total, the agent names of at most 5 user-agent groups (only names on our list of known agent tokens, at most 8 per group; any other name is only counted), at most 5 names of keys we could not read, the parser version and the robots.txt hash. For a status page we find automatically, we also keep the evidence that it belongs to the host (its DNS delegation), the page address and the operator that recorded it. A lookup that needs a fresh read leaves a background-read request (the public hostname, the kind of read and when it was asked for), which is deleted as soon as the read is done, or after five failed attempts. We also keep the current copy of each public government domain list we download (the U.S. .gov list and the UK .gov.uk list): for each domain its name and, for the U.S. list, the domain type, organisation, sub-organisation and state; the security contact email address and the city that the U.S. file contains are not kept. With each list we keep its version date, the address it was downloaded from, a SHA-256 hash of the file as received, the reader version, the operator and declared network location that made the download, and the time of the last check. Each copy is replaced when its publisher posts a new version, and the replaced rows are deleted; a download that fails or looks wrong leaves the previous copy in place. {% if reporting_enabled %}Daily report-intake totals, the incident records that group reports by hostname, task step and error type, and audit-log entries (event type, report ID and time) also contain no personal data and have no automatic deletion date. {% if report_retention_days %}Reports are deleted {{ report_retention_days }} days after they are received; a withdrawn report is excluded from every read at once and deleted 30 days after withdrawal. {% else %}Reports have no automatic deletion date during the beta; a withdrawn report is excluded from every read at once. {% endif %}Public reads show only the last 7 days, and we delete a report sooner on request. {% endif %}Rate-limit counters stay in memory for about one minute and are never written to disk. Support emails are kept only as long as needed to handle the request. An hourly cleanup job deletes expired rows from the database; copies in the hosting provider's database backups expire under that provider's backup schedule. Render and Cloudflare keep their own delivery and security logs under their own retention terms.{% if public_bundle %} Offline data bundle: the latest file and the day's total of bytes served (no client data) are kept in one database row, replaced on each daily build and deleted when the bundle is switched off. Download limits per client are counted in memory only, under a keyed daily digest of the IP address, and are never stored.{% endif %}

Your controls

Send only public hostnames and the structured codes above. {% if reporting_enabled %}Keep the withdrawal token from your receipt: DELETE /v1/observations/{id} with that token removes your report from all reads at once. report_observation is a separate write action that your AI client may ask you to confirm; check_incident is read-only. {% endif %}You can disconnect the app in ChatGPT or remove the MCP server from your client at any time. Email support@agenthelpnetwork.com to ask what we hold about a report or request, or to correct or delete it; include the report ID if you have it. Depending on where you live, you may have further rights such as access, deletion or objection, and you can exercise them the same way. We aim to answer within 30 days.

수집하는 데이터

계정이나 로그인은 없습니다. check_incident 도구는 공개 호스트명(site_host)과, 정해진 목록에서 고르는 선택 코드 error_class·task_step·failure_stage 만 받습니다. 전체 URL·경로·쿼리 문자열은 거부합니다. {% if reporting_enabled %}report_observation 도구와 제보 양식은 공개 호스트명, 작업 단계, 오류 유형, 관찰 시각, 에이전트 계열, 시도 주체·환경, 결과, 사람 확인 업체·종류 코드, 가상 여부, 중복 방지 키만 받습니다. 모든 필드는 호스트명·시각·정해진 목록의 값이며 자유 입력 문장은 받지 않습니다. 제보마다 들어온 경로(웹사이트·REST API·MCP 도구)와, 그 제보를 받은 운영자 및 그 운영자의 제보 ID 도 함께 기록합니다. {% endif %}웹사이트와 REST API 도 같은 필드만 받습니다. 요청마다 IP 주소와 User-Agent 가 네트워크 경계·호스팅 업체에 전달되지만, 우리 데이터베이스에는 아래 보존 항목의 파생 집계만 남기고 원문은 저장하지 않습니다. AI 클라이언트가 도구 호출에 붙일 수 있는 언어 설정·대략적 위치 같은 메타데이터는 읽거나 저장하지 않으며, 추적·광고 쿠키를 쓰지 않습니다. 지원 메일을 보내면 보낸 주소와 내용을 받습니다. 이름·연락처·정밀 위치·결제 정보·대화 내용은 요구하지 않으며, 도구는 개인 URL 과 자유 입력을 거부하도록 만들어져 있습니다.

03

도구가 돌려주는 것

check_incident 는 공개된 호스트 단위 정보만 돌려줍니다. 호스트가 robots.txt·llms.txt 로 선언한 정책(robots.txt 가 선언한 콘텐츠 이용 선호 포함), 정리된 공식 개발자·상태 링크, 업체가 발표한 상태, 제보자 신원이 없는 공개 관찰, 대략적인 조회 활동 구간, 그리고 공개 정부 도메인 목록에 있거나 접미사가 정부 기관 전용인 도메인에 대해서는 도메인에 관한 레지스트리 사실입니다. 레지스트리 사실은 그 도메인이 올라 있는 미국 .gov 목록 또는 영국 .gov.uk 목록, 그 목록에 적힌 기관명, 접미사에 대한 레지스트리 규칙입니다. 이는 도메인에 관한 사실이며 사이트·페이지·링크에 대한 판단이 아닙니다. {% if reporting_enabled %}report_observation 은 관찰·사건 ID, 검토 상태, 그 제보의 철회 토큰이 담긴 접수증을 돌려줍니다. {% endif %}어떤 응답에도 다른 사람의 개인정보는 들어 있지 않습니다.

데이터를 받는 곳

{% if reporting_enabled %}일반 공개: 검토를 통과한 제보는 구조화 필드만 담긴 미검증 관찰로, 제보자 신원 없이 공개 화면과 API·MCP 응답에 나옵니다. {% endif %}조회량은 대략적인 구간으로만 공개합니다. 우리를 대신해 데이터를 처리하는 업체: Render(앱 호스팅·데이터베이스, 미국)와 Render 의 네트워크 경계를 운영하는 Cloudflare, Porkbun(도메인 이름 서비스·지원 주소의 메일 전달)과 그 메일이 전달되는 메일함 업체입니다. 읽기 대상 웹사이트: 호스트의 robots.txt·llms.txt 나 업체 상태 피드를 읽을 때 그 호스트는 AgentHelpNetwork 로 표시된 우리 서버의 요청만 보며, 이용자에 관한 정보는 담기지 않습니다. 이 읽기는 조회가 기다리는 동안이 아니라 조회 뒤에 따로 이루어집니다. 공개 정부 도메인 목록: 미국 .gov 레지스트리의 공개 데이터 저장소(raw.githubusercontent.com)에서 약 하루에 한 번, GOV.UK 에서 약 한 달에 한 번 두 목록을 게시자로부터 통째로 내려받습니다. 이 요청에는 호스트명도 이용자에 관한 정보도 담기지 않고 AgentHelpNetwork 로 표시되며, 목록에 적힌 사이트에는 접속하지 않습니다. 운영자는 저장한 데이터를 자체 용도로 내보낼 수 있으며, 이 운영자용 내보내기는 공개 엔드포인트가 아니고 내보낸 제보에는 공개 응답에 나오는 필드만 담깁니다. {% if public_bundle %}오프라인 데이터 묶음: 누구나 /v1/bundle/latest.jsonl.gz 에서 받을 수 있는 파일로, 하루 한 번 정도 다시 만들어 CC BY 4.0 으로 공개합니다. 원본에서 누구나 다시 확인할 수 있는 데이터만 담습니다: 공개 시드 목록 중 큐레이션한 부분에 있는 호스트의 robots.txt·llms.txt 판독 결과, 큐레이션한 공식 개발자 경로(이용 정보 포함. 그 안의 업체 문서 짧은 인용은 업체의 저작물이라 이 라이선스 대상이 아닙니다), 큐레이션한 상태 페이지 매핑입니다. 매핑한 호스트 중 상당수는 Tranco 인기 순위의 구간을 훑어 찾았지만, 매핑마다 그 호스트의 상태 페이지에서 직접 확인했으며 순위는 담지 않습니다. 판독 시각은 날짜까지만 적습니다. 제보, 시드 목록에 없는 조회된 호스트명, 조회 수, 요청 기록, IP 변환값, 제보자 키, 상태 피드의 현재 값, 제3자 인기 순위에서만 가져온 시드 호스트, 시드 목록의 순서나 순위는 절대 담지 않습니다. {% endif %}법이 요구할 때만 당국에 제공합니다. 그 밖의 누구와도 공유하지 않습니다.

보존 기간

비밀키로 날짜별 변환한 IP 값과 일별 요청 수: 14일. 유입·캠페인 분류 집계와 결과 범주별 MCP 도구 호출 수: 90일. 호스트별 일일 제보 접수 수: 8일. 호스팅 업체 Render 의 시간별 사용량 표본(CPU·메모리·요청 합계): 90일. 조회된 호스트명 목록: 30일 동안 조회가 없으면 삭제(공식 상태 피드가 연결된 호스트는 예외). 큐레이션한 공개 호스트명별 robots.txt 읽기 이력(시각, 읽은 호스트, 상태, 라벨, 분류, 운영자, 선언한 네트워크 위치, 그 구간의 보류 여부와 사유): 14일. 큐레이션한 호스트의 robots.txt 를 읽지 못한 구간이나 업체가 문제를 발표한 구간, 그리고 업체가 발표한 상태의 각 변화: 90일(마지막 변화 기준)이며, 업체가 아직 문제를 발표 중인 구간은 끝날 때까지 둡니다. 호스트별 일일 robots.txt 읽기·응답·실패·거절·보류 합계와 조회 뒤 읽기 수·시드 목록 읽기 수: 90일. 이 이력에는 개인정보가 없습니다. 공개 호스트명·오류 유형별 일일 조회 수와 경로별 요청 수는 개인정보가 없으며 자동 삭제 기한이 없습니다. 공개 호스트명별로 저장한 robots.txt·llms.txt 해석 결과와 업체 상태 캐시도 자동 삭제 기한이 없습니다. 캐시한 결과마다 받은 파일·피드의 SHA-256 해시(원문은 저장하지 않음), 읽기 프로그램 버전, 읽은 운영자와 선언한 네트워크 위치를 함께 둡니다. robots.txt 결과마다 그 파일이 선언한 콘텐츠 이용 선호(Content-Signal·Content-Usage 줄)를 yes·no·unset 으로 정규화한 값, 경로 표본 전체 최대 3개, user-agent 그룹 최대 5개의 에이전트 이름(알려진 에이전트 토큰 목록에 있는 이름만, 그룹당 최대 8개, 그 밖의 이름은 개수만), 읽지 못한 키 이름 최대 5개, 해석기 버전과 robots.txt 해시도 함께 둡니다. 자동으로 찾은 상태 페이지에는 그 호스트의 것이라는 근거(DNS 위임), 페이지 주소, 기록한 운영자도 둡니다. 새로 읽어야 하는 조회는 뒤에서 읽기 요청(공개 호스트명, 읽기 종류, 요청 시각)을 남기며, 이 요청은 읽기가 끝나면 바로, 다섯 번 실패하면 그때 삭제합니다. 또 우리가 내려받는 공개 정부 도메인 목록마다 현재 사본을 둡니다(미국 .gov 목록, 영국 .gov.uk 목록). 도메인마다 이름과, 미국 목록은 도메인 유형·기관명·하위 기관명·주를 두며, 미국 파일에 들어 있는 보안 연락 이메일 주소와 도시는 두지 않습니다. 목록마다 판본 날짜, 내려받은 주소, 받은 파일의 SHA-256 해시, 읽기 프로그램 버전, 내려받은 운영자와 선언한 네트워크 위치, 마지막 확인 시각도 둡니다. 각 사본은 게시자가 새 판을 내면 교체되고 교체된 행은 삭제되며, 내려받기가 실패하거나 이상해 보이면 이전 사본을 그대로 둡니다. {% if reporting_enabled %}일별 제보 접수 합계, 제보를 호스트명·작업 단계·오류 유형으로 묶는 사건 기록, 감사 기록(이벤트 유형·제보 ID·시각)도 개인정보가 없으며 자동 삭제 기한이 없습니다. {% if report_retention_days %}제보는 접수 {{ report_retention_days }}일 뒤 삭제됩니다. 철회한 제보는 즉시 모든 조회에서 빠지고 철회 30일 뒤 삭제됩니다. {% else %}제보는 베타 기간 동안 자동 삭제 기한이 없으며, 철회한 제보는 즉시 모든 조회에서 빠집니다. {% endif %}공개 조회는 최근 7일만 보여 주며, 요청하면 더 일찍 삭제합니다. {% endif %}요청 상한 계수는 약 1분간 메모리에만 있고 디스크에 쓰지 않습니다. 지원 메일은 요청 처리에 필요한 동안만 보관합니다. 만료된 행은 매시간 도는 정리 작업이 데이터베이스에서 삭제하며, 호스팅 업체의 데이터베이스 백업에 남은 사본은 그 업체의 백업 주기에 따라 만료됩니다.
