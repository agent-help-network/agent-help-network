# 허위 제보와 반복 공격 대응

작성일: 2026-10-03. 사이드프로젝트 규모에 맞춘 단계별 방어 계획이다. 실제 공격·허위 제보가 이미 있었다는 뜻이 아니다. 사용자의 접근성 우선 결정에 따라 **현재 베타는 계정·토큰 발급 없이 접수하고, 규칙 기반 자동 검토 후 일부를 미확인 관찰로 공개한다.** 의심 제보는 비공개로 보류한다. 아래 토큰 발급 항목은 남용이 확인될 때 검토할 후속 방안이다. 현재 구현은 [공개 제보 운영 절차](public-intake-operations.md)를 따른다.

## 다른 서비스에서 확인한 방식

| 공식 사례 | 확인된 방식 | 우리 적용 |
| --- | --- | --- |
| [GitHub REST API 제한](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api?apiVersion=2026-03-10) | 기본 요청 한도 외에도 집중 요청·동시 요청·콘텐츠 생성에 별도 제한을 둔다. | 읽기, 토큰 발급, 제보를 별도 한도로 다룬다. 제보가 더 높은 비용을 갖는다. 수치는 실제 트래픽을 보고 조정한다. |
| [MediaWiki AbuseFilter](https://www.mediawiki.org/wiki/Extension%3AAbuseFilter/Actions/en) | 기록, 경고, 제한, 저장 거부, 되돌리기를 단계적으로 쓴다. 공유 IP만으로 제한하면 오탐 가능성도 언급한다. | 구조화된 제보 검증, 출처별 제한, 의심 기록 숨김, 권한 중지, 사건 요약 갱신을 제공한다. IP 단독 차단에 의존하지 않는다. |
| [Cloudflare Turnstile](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/) | 웹 폼의 봇 검증 토큰은 서버가 검증해야 한다. | 익명 토큰 발급/웹 제보 폼에 필요할 때 적용한다. 에이전트 API의 제보 진실성을 보증하는 장치로 취급하지 않는다. |
| [Cloudflare 방어 구성](https://developers.cloudflare.com/use-cases/solutions/stop-malicious-bots/) | 봇 방어, WAF, 속도 제한을 층으로 조합한다. | 호스팅 선택 시 기본 DDoS·WAF·경로별 속도 제한을 확인한다. 애플리케이션의 권한·데이터 검증은 직접 구현한다. |

## 공개 베타 최소 방어

1. **내용 제한:** 호스트·단계·오류·시도 주체/환경·결과의 닫힌 필드만 받는다. URL·개인 정보·자유 서술은 거부한다.
2. **제보 출처:** 현재 쓰기도 계정 없이 가능하고 모든 익명 제출은 하나의 미확인 출처로 묶는다. 서로 다른 제출을 독립된 사람으로 세지 않는다. 필요할 때만 익명 토큰 발급·폐기를 추가한다.
3. **제출 제어:** 멱등 키, 앱의 클라이언트·전체 분당 제한, DB의 전체·호스트별 하루 제한을 적용한다. 초과 요청은 `429`다. 봇 방어나 토큰은 악용이 확인되면 추가한다.
4. **증거 표시:** 단일 출처는 미확인으로 표시한다. 상충하는 성공·실패를 모두 남기고 오래된 관찰의 우선순위를 낮춘다. 여러 토큰도 독립 사용자라고 단정하지 않는다.
5. **운영 대응:** Render의 별도 규칙 스크립트가 제한된 건을 공개하고 반복·이상 입력을 보류한다. 운영자가 보류 건을 게시하거나 잘못된 관찰을 숨길 수 있다. 제보자는 철회 토큰으로 자기 제출을 조회에서 제외한다. 새 제보 접수는 DB 스위치로 잠시 끌 수 있다.
6. **트래픽 방어:** 요청 본문·결과 크기 제한, 경로별 요청 제한, DB 연결 한도, 호스팅 측 WAF/DDoS 보호. 읽기 장애와 쓰기 장애를 모니터링한다.
7. **조사와 복구:** 민감 원문을 로그에 복사하지 않고 최소 감사 이벤트로 추적한다. 키 유출·허위 제보·과부하 대응 절차와 복구 시험을 준비한다.

## 판정의 한계

이 장치들은 거짓 정보를 줄이고 수정하는 수단이다. 제보가 참이라고 자동 판별하지 못한다. 조회 횟수 또한 실제 실패 건수가 아니다. 공개 화면은 확정 상태보다 증거 수준과 관찰 시각을 보여준다. 호스팅 업체가 대량 요청을 막아 주더라도 허위 내용의 판정과 정정은 서비스가 맡는다.
