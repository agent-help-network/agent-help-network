| D26 (2026-10-17 접근 프로필 전환) | 조회 응답을 세 층으로 재정의한다: ① `access_profile` — 호스트 자체 `robots.txt`(RFC 9309)의 에이전트 토큰별 규칙과 `llms.txt` 존재 여부(**선언된 정책**), ② `official_paths`(정리된 표) + 기존 업체 상태, ③ 기존 `observations`(선택). 제품 문장은 "공개 호스트명 하나로 묻는다: 이 호스트는 에이전트에게 무엇을 허용하는가, 공식 경로는 무엇인가, 지금 정상인가 — 그리고 다른 에이전트의 최근 관찰이 있는가"로 고정한다. | (1) 실사용에서 거의 모든 조회가 `no_reports` 로 끝나 제보 층만으로는 답이 비어 있었다. 제보는 이제 답의 한 줄이며 `no_reports` 가 보통이다. (2) 막힌 에이전트에게 당장 쓸모 있는 것은 호스트가 스스로 선언한 정책과 공식 경로다. 이는 호스트의 공개 파일과 공개 문서에서 탐침 없이 얻을 수 있다. (3) 한계를 그대로 표기한다: 선언된 크롤러 정책은 접근 보장이 아니고 CDN·로그인은 사용자 지시 에이전트를 다르게 취급할 수 있으며, 목록에 없는 호스트는 공식 경로가 없다는 뜻이 아니다. 읽기는 공개 루트 호스트·공개 IP·리디렉션 없음·크기 상한·24시간 캐시·호스트당 하루 한 번으로 제한하고, 탐침 금지·실패 조작 금지·제휴 암시 금지는 그대로다. `check_incident` 는 호출자 관점에서 읽기 전용·멱등으로 주석한다(D25 의 집계 부수효과는 유지). **2026-10-18 보충:** 이후 구현은 리디렉션을 한 번까지만 따른다. 호스트에서 같은 경로의 자기 `www.` 별칭으로 가는 한 단계만 따르고 다른 리디렉션은 `redirected` 로 기록하며 따라가지 않는다. 확정된 답은 24시간 캐시하고 전송 실패는 1시간 뒤 다시 시도한다. 현재 동작은 README 와 `docs/api-contract.md` 를 따른다. |
| D27 (2026-10-18) | 외부 읽기의 결과를 성공·없음·거절·형식 오류·전송 실패·비공개로 나누고, 실패에는 사유 라벨을 남긴다. 전송 실패만 1시간 뒤 다시 읽는다. | 거절은 그 자체가 에이전트에게 쓸모 있는 신호다. 전송 실패를 하루 캐시하면 틀린 답이 하루 종일 나간다. |
