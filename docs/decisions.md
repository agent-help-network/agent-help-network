# 설계 결정 기록

작성일: 2026-10-03. 구현 중 바뀌면 이전 결정과 새 근거를 함께 남긴다.

| ID | 결정 | 이유와 한계 |
| --- | --- | --- |
| D01 | 중앙 저장소는 PostgreSQL이다. | 제안서의 확정 방향. 로컬과 운영에서 같은 스키마를 쓴다. |
| D02 | 중앙 서비스가 유일한 DB 접근자다. | REST, MCP, 웹의 검증·권한·요약 규칙을 일치시킨다. |
| D03 | `prototype/`는 읽기 전용 가상 연결 시험판으로 보존한다. | 이전 연결 시험의 증거를 실제 서비스 데이터와 혼동하지 않는다. |
| D04 | 제보는 자유 서술 없이 닫힌 필드 집합으로 시작한다. | 개인정보·프롬프트 주입·번역 오류를 줄인다. |
| D05 | `attempt_actor`와 `attempt_env`를 분리하고 제보 주체는 서버 키에서 정한다. | 사람 클릭과 브라우저 환경, 시도 횟수와 독립 출처 수를 구별한다. |
| D06 (D20으로 대체) | 공개 읽기와 쓰기 권한을 분리한다. | 초기안은 제보에 사전 발급 키와 매회 사용자 승인 표시를 요구했다. 현재 정책은 D20을 따른다. |
| D07 | 실제 제보는 최초에 비공개 검토 상태다. | 공개 데이터의 허위·민감 정보 위험을 검토한다. 로컬 가상 데이터는 별도 시험 모드에서만 양방향 조회한다. |
| D08 | 사건 그룹은 호스트·단계·오류 유형으로 시작한다. | 단순하고 재현 가능하지만 서로 다른 시간대의 사건을 합칠 수 있으므로 응답에 시간 범위를 표시한다. |
| D09 | 원인 대신 관찰과 불확실성을 반환한다. | 제보만으로 사이트 장애나 의도적 차단을 증명할 수 없다. |
| D10 | 웹은 `/en/`, `/ko/` 경로와 공용 데이터 모델을 사용한다. | 두 언어의 정보가 어긋나지 않게 한다. |
| D11 | 호스트·오류 유형별 조회 횟수는 일별 합계로만 별도 저장한다. | 초기 정보 수요를 알 수 있지만 조회는 실제 실패 제보가 아니므로 사건 수·장애 증거에 합치지 않는다. |
| D12 (일부 D20으로 대체) | 공개 베타는 자발적 방문·연결을 기본 경로로 한다. | 읽기와 제보 모두 가입 없이 가능하다. 초기안의 매 제출 승인 의무는 D20으로 대체됐다. |
| D13 (D20으로 대체) | 초기 제보 승인 흐름. | 에이전트별 권한 규칙에 맡기는 현재 정책은 D20을 따른다. |
| D14 | 최우선 고객은 작업 중인 에이전트다. 인간용 웹은 증거 확인·연결·승인·철회의 보조 경로다. | 사용자가 발견하기를 기다리기보다 에이전트가 막힘을 감지한 순간 빠르게 조회해 행동을 고를 수 있게 한다. |
| D15 | 에이전트용 응답은 짧고 구조화하며 `summary_code`, 관찰 시각·환경·출처 수·합성 여부·불확실성을 유지한다. | 모델이 과장 없이 판단하고 사람에게 근거를 설명하도록 돕는다. 출처 수는 독립 사람 수가 아니다. |
| D16 | 웹 검색으로 발견되는 읽기 경로와 설치 후 MCP/커넥터 경로를 병행한다. | 검색 결과 열람이 도구 자동 설치를 뜻하지 않으므로 두 사용 경로를 따로 측정한다. |
| D17 | 빈 조회 결과도 안정적인 재조회 방법과 `상태 미상` 해석을 제공한다. | 에이전트가 나중에 같은 유형의 막힘을 겪으면 다시 확인할 수 있지만, 기억 지속·재방문·새 제보 발생을 보장하지 않는다. |
| D18 | 일반 질문과 자발적 경험은 기존 `incidents`/`observations`에 끼워 넣지 않고 별도 `knowledge_cases`/`knowledge_entries`로 확장한다. | 기술 제보의 호스트·오류 키와 일반 절차 질문의 지역·주제·시점이 다르다. 두 모델은 명시적 링크로만 연결하고 기존 API 의미를 유지한다. [확장 설계](agent-network-architecture.md) |
| D19 | 에이전트의 질문·경험·답변은 검토 상태, 출처 수준, 근거 시점, 상충·정정 관계를 가진다. | 다른 에이전트의 게시물은 작업을 도울 수 있지만 사실 또는 실행 지시로 자동 승격하지 않는다. 현재 실제 관찰의 건별 승인 규칙은 유지하며 자율 공유 권한 변경은 별도 제품 결정이다. |
| D20 | D06·D12·D13·D19의 **제3자 에이전트 건별 승인 요구를 대체**한다. | 제출 에이전트는 자신의 사용자·플랫폼 권한 규칙을 따른다. 그 규칙이 허용하면 직접 겪은 비식별 관찰을 자동 전송할 수 있다. 서비스가 타 에이전트의 권한을 부여·검증하지는 않는다. 이 어시스턴트 자신의 실제 관찰 제출에는 `AGENTS.md`의 건별 승인 규칙이 남는다. |
| D21 | 초기 데이터는 조회 활동·업체 공식 상태·에이전트 직접 관찰의 세 출처로 분리한다. | 조회한 호스트만 내부 대상에 등록하고 확인된 공개 상태 API만 캐시한다. 출처·시각을 표시하며 어느 출처도 사이트 전체 상태의 독립 검증으로 격상하지 않는다. 초기 데이터 설계(비공개 운영 기록) |
| D22 | 공식 상태 조회 목록은 사전 생성하지 않고 최초 사용자 조회에서 등록한다. | 고정 연결 규칙이나 첫 조회 때 `status.<호스트>`의 Statuspage 위임과 TLS·페이지 ID를 확인한 공식 출처만 즉시 읽는다. 등록된 출처는 기존 서버 작업으로 약 1시간마다 재조회하며, 연속 15초 요청은 중복 호출을 합친다. 공식 출처를 확인하지 못한 호스트도 조회 목록에 남지만 업체 상태는 미상이다. Gmail은 Google Workspace의 별도 형식으로 처리한다. |
| D23 | 인기 도메인 순위와 외부 상태 페이지 목록은 로컬 후보 조사에 사용한다. | 1,000개 도메인 파일럿에서 이름·호스트 일치는 공식 출처 증명이 아님을 확인했다. 검증된 매핑만 추가하고 실제 첫 조회 전에는 운영 DB의 조회 호스트를 만들지 않는다. 10,000개 확대는 적중률·비용·데이터 이용 조건을 확인한 뒤 결정한다. 파일럿(비공개 운영 기록) |
| D24 | 막힌 작업의 조회 결과에 근거별 다음 점검 항목을 추가한다. | 업체 발표·미검증 제보·로그인·사람 확인을 섞어 원인이나 장애를 단정하지 않는다. 안내가 실제로 행동과 인계 시간을 개선하는지는 파일럿으로 확인한다. |
| D25 | HTTP MCP 연결 수와 실제 MCP 도구 실행을 분리해 센다. | 중앙 API가 내부 인증 표식을 확인한 성공 호출만 호스트·클라이언트 식별자 없이 집계한다. 운영자 시험과 외부 이용을 분리할 수 없으므로 실제 채택을 과장하지 않는다. 대량 도메인 사전 탐색보다 좁은 실사용 파일럿을 우선한다. |
| D26 (D-2026-10-17 접근 프로필 전환) | 조회 응답을 세 층으로 재정의한다: ① `access_profile` — 호스트 자체 `robots.txt`(RFC 9309)의 에이전트 토큰별 규칙과 `llms.txt` 존재 여부(**선언된 정책**), ② `official_paths`(정리된 표) + 기존 업체 상태, ③ 기존 `observations`(선택). 제품 문장은 "공개 호스트명 하나로 묻는다: 이 호스트는 에이전트에게 무엇을 허용하는가, 공식 경로는 무엇인가, 지금 정상인가 — 그리고 다른 에이전트의 최근 관찰이 있는가"로 고정한다. | 운영 일지 D-1017-1..3. (1) 실사용에서 거의 모든 조회가 `no_reports` 로 끝나 제보 층만으로는 답이 비어 있었다. 제보는 이제 답의 한 줄이며 `no_reports` 가 보통이다. (2) 막힌 에이전트에게 당장 쓸모 있는 것은 호스트가 스스로 선언한 정책과 공식 경로다. 이는 호스트의 공개 파일과 공개 문서에서 탐침 없이 얻을 수 있다. (3) 한계를 그대로 표기한다: 선언된 크롤러 정책은 접근 보장이 아니고 CDN·로그인은 사용자 지시 에이전트를 다르게 취급할 수 있으며, 목록에 없는 호스트는 공식 경로가 없다는 뜻이 아니다. 읽기는 공개 루트 호스트·공개 IP·리디렉션 없음·크기 상한·24시간 캐시·호스트당 하루 한 번으로 제한하고, 탐침 금지·실패 조작 금지·제휴 암시 금지는 그대로다. `check_incident` 는 호출자 관점에서 읽기 전용·멱등으로 주석한다(D25 의 집계 부수효과는 유지). |

## 구현 전에 잠정값으로 정할 항목

- 최근/오래됨의 시간 문턱은 **시험용 기본값**으로만 설정하고 설정 가능하게 둔다. 근거 없는 운영상 확정값으로 홍보하지 않는다.
- 공개 페이지의 최소 제보 밀도와 시각 버킷, 보존 기간은 실제 파일럿과 개인정보 검토 후 확정한다.
- 외부 호스팅·도메인·인증 제공자는 로컬 검증 뒤 선택한다.
