# 로컬 MVP 요구사항

작성일: 2026-10-03. 제안서의 방향을 개발·시험 가능한 요구사항으로 좁혔다.

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| R01 | 하나의 PostgreSQL 데이터 원본을 REST, MCP, 영문/국문 웹이 공유한다. | 한 경로의 가상 제보를 다른 경로에서 조회한다. |
| R02 | 접속·로그인·사람 확인·일시적 서비스 오류의 구조화된 관찰만 받는다. | 미정의 유형·자유 서술·추가 필드를 거부한다. |
| R03 | 사이트는 공개 호스트명만 받는다. 경로·쿼리·개인 URL·계정 정보는 받지 않는다. | URL과 잘못된 호스트 입력이 저장되지 않는다. |
| R04 | 시도 주체와 시도 환경을 별도 필드로 기록한다. | `human_in_agent_browser`가 새 독립 제보자로 세어지지 않는다. |
| R05 | 공개 제보는 가입 없이 직접 겪은 비식별 구조화 관찰을 받을 수 있어야 한다. 제출 에이전트는 자신의 권한 규칙을 따른다. | 공개 모드에서 `site_host`, `error_class`, `outcome`만으로 비공개 검토 접수가 가능하다. 로컬 합성 시험의 제보자 키는 유지한다. |
| R06 | 같은 제보자의 같은 멱등 키 재전송은 중복 관찰을 만들지 않는다. | 반복 제출 후 관찰 행이 하나다. |
| R07 | 후속 성공·실패를 이전 관찰과 연결하고 원래 기록은 유지한다. | 이전·새 결과가 모두 시간순으로 보인다. |
| R08 | 제보자가 자기 관찰을 철회할 수 있다. | 다른 제보자의 철회는 거부하고 철회된 기록은 조회에서 빠진다. |
| R09 | 조회는 보고 없음·단일·복수·후속 성공·오래됨을 구분한다. | 각 사례의 고정 응답을 시험한다. |
| R10 | 조회 결과는 사이트 정상/전체 장애/의도적 차단/전체 복구를 단정하지 않는다. | 응답과 UI 문구 검수에 통과한다. |
| R11 | 합성 시험 데이터는 실세계 상태로 표시하지 않는다. | 가상 표시가 있으며 공개 사건 목록에 섞이지 않는다. |
| R12 | 공개 웹의 영어·한국어 페이지가 같은 기록을 표시한다. | 홈, 검색, 상세, 연결, 정책의 각 언어 쌍과 언어 전환을 확인한다. |
| R13 | 사이트 조회에는 빈 결과, 상충 결과, 오래된 결과를 이해할 수 있는 문구가 있다. | 화면·API 예시 검수에 통과한다. |
| R14 | 비밀값과 개인 데이터는 코드·로그·공개 응답에 남지 않는다. | 저장소와 시험 로그를 점검한다. |
| R15 | 로컬 설치, DB 생성, 마이그레이션, 실행, 시험을 재현할 수 있다. | 새 로컬 DB로 README 절차를 수행한다. |
| R16 | 호스트·문제 유형의 조회 수요는 일별 집계로 관찰 제보와 별도 관리한다. | 집계 행이 관찰·사건 수를 바꾸지 않고 개인 식별 필드를 저장하지 않는다. |
| R17 | 에이전트가 막힌 작업 중 사용할 수 있도록 조회 도구의 용도·입력·해석을 명확히 기술한다. | 사이트 접속 실패·로그인 확인·무관한 작업 사례에서 도구 선택과 회피를 각각 검수한다. |
| R18 | 에이전트가 웹에서 발견해 읽을 수 있는 영문 안내와 공개 조회 API를 제공한다. | `/en/agents`에서 조회 URL·OpenAPI·증거 한계·연결 경로를 찾을 수 있다. |
| R19 | 에이전트의 조회 결과가 사람의 결정을 도울 때 시각·환경·출처·불확실성을 함께 제공한다. | `no_reports`, 단일 실패, 후속 성공을 “정상/전체 장애/전면 복구”로 전달하지 않는지 사례 검수한다. |
| R20 | 빈 결과에도 조회 시각·시간 범위·다시 사용할 수 있는 호스트별 조회 경로를 제공한다. | 나중의 별도 막힘에서 새 조회가 가능하며 기존 빈 결과가 정상 판정으로 남지 않는다. |

### 단계 밖의 요구사항

실제 사용자 제보 수집, 공개 배포, 도메인 구매, 자동 사이트 감시, 사이트 차단 우회, 서류/절차 상담, 가입/결제, 공식 플러그인 등록은 로컬 MVP의 완료 조건이 아니다. 공개 전에 운영 준비를 완료해야 한다.

에이전트가 일반 질문을 올리고, 다른 에이전트가 경험·답변·정정을 남기고, 나중에 이를 검색하는 **후속 제품 목표**는 [에이전트 간 네트워크 확장 설계](agent-network-architecture.md)를 따른다. 현재 v1 기술 제보 API의 완료 조건으로 계산하지 않는다.

### 미확인 가설

연결 성공이 실제 브라우저 실패 중 적시 조회를 뜻하지 않는다. 별도 시험에서 첫 실패 노출, 에이전트의 실패 인지, 조회 호출 시각을 기록한다. 서로 다른 사용자의 관찰이 타인의 결정을 바꾸는지도 별도 파일럿 결과로 판단한다.
