# 공개 제보 접수·검토·중지 절차

작성일: 2026-10-03. 계정 없는 간단한 제보를 허용한다는 사용자 결정을 반영한다. 검토 전 제보는 공개 조회에 나타나지 않는다. 이 문서는 운영 절차이며 제보의 진위를 자동 판정한다는 뜻이 아니다.

## 접수 범위

- 사람용 `/en/report`, `/ko/report`; 에이전트용 `POST /v1/observations`, MCP `report_observation`. 조회는 계속 계정 없이 가능하다.
- 공개 호스트명, 일반 작업 단계, 문제 종류, 관찰 시각, 시도 주체·환경, 결과, 범주형 확인 화면 정보만 받는다. 자유 서술, 개인 URL, 계정·이름·비밀번호·쿠키·대화 전문은 허용하지 않는다.
- 에이전트는 자신의 사용자·플랫폼 권한 규칙을 따르며, 허용되는 범위에서 직접 겪은 비식별 관찰을 자동 전송할 수 있다. 서비스는 다른 에이전트의 건별 승인 절차를 정하거나 검증하지 않는다. 과거 클라이언트 호환용 `consent_confirmed`는 선택 필드이며 권한 판단에 사용하지 않는다. 사람용 폼은 제출자가 필드를 확인하도록 체크박스를 유지한다.
- 접수된 관찰은 `pending`, 사건은 비공개로 시작한다. Render의 별도 Cron Job이 5분마다 대기열을 일괄 처리한다. 익명 제보는 모두 하나의 미확인 출처로 계산한다. 여러 건이라도 독립적인 사용자가 보고했다는 뜻은 아니다.
- `201` 응답에는 관찰 ID와 철회 토큰이 들어 있다. 토큰을 가진 사람은 웹 폼 또는 `DELETE /v1/observations/{id}`의 `X-Withdrawal-Token` 헤더로 해당 관찰을 조회에서 제외할 수 있다. 토큰을 URL이나 로그에 남기지 않는다.

## 접수 제한과 자동 검토

- 단일 웹 인스턴스의 제보 제한: 클라이언트당 분당 3건, 전체 분당 20건. DB 제한: 전체 하루 100건, 같은 호스트 하루 5건(`www.<루트>`는 루트 호스트와 한 호스트로 센다. 제보 자체는 정확한 `site_host`로 저장된다). 요청 본문은 최대 4096바이트, JSON만 허용한다. 클라이언트 구분 키는 호스팅 경계가 덮어쓰는 `CF-Connecting-IP`이며, 경계가 없는 로컬 실행에서만 `X-Forwarded-For`로 폴백한다. MCP 어댑터가 같은 앱을 루프백으로 다시 부르는 내부 홉은 HMAC 표식으로 식별해 이중으로 세지 않는다. 전체 제한과 DB 제한이 최종 방어다.
- `python -m ahn.auto_review`는 접수 후 10분 지난 제보를 최대 100건씩 검사한다. `blocked`·`error`·`passed` 결과를 같은 기준으로 다루고, `abandoned`는 보류한다. 제한된 공개 최상위 호스트(그 앞에 `www.` 라벨 하나만 붙은 이름 포함), 허용 단계, 24시간 이내 관찰만 통과할 수 있다. 같은 호스트의 15분 내 3건 이상, 최근 24시간 내 같은 결과가 이미 공개된 호스트·사건 반복은 보류한다. 이 두 호스트 창에서 `www.<루트>`와 루트 호스트는 한 호스트로 센다. 둘로 나눠 보낸 제보 한 쌍이 같은 사이트의 공개 속도를 두 배로 만들지 못하게 하려는 것이다. 합쳐 세는 것은 보류 판단뿐이며, 제보와 사건은 정확한 `site_host`에 그대로 저장·공개된다. 다른 서브도메인(`shop.<루트>`, `www.www.<루트>`)은 이전처럼 `unreviewed_subdomain`으로 보류한다. 통과한 건만 `auto_unverified`로 표시해 공개한다. 외부 사이트에 접속하거나 상태를 진단하지 않는다. 이 규칙은 허위 내용이나 실제 동의 여부를 증명하지 못한다.
- 보류 제보는 `review_reason`과 감사 이벤트를 남긴다. `/owner` 운영 모니터의 최근 보류 목록과 `python -m ahn.cli pending-reports --limit 20`에서 확인한다. 자동 검토 작업이 실패하면 비공개 대기 상태를 유지한다.
- 보류된 ID의 공개 호스트명·범주·시각을 운영자가 검토하고 비정상 반복, 개인 식별자로 보이는 단계, 모순된 분류 등을 살핀다. 출처의 진위와 사이트 상태는 확인되지 않은 것으로 취급한다.
- 게시할 기록은 `python -m ahn.cli publish-observation UUID`; 게시하지 않을 기록은 `python -m ahn.cli hide-observation UUID`. 두 작업은 감사 이벤트를 남긴다. 공개 후 오류가 발견되면 즉시 숨긴다. 운영자가 확인하지 못한 제보는 계속 비공개로 둔다.
- `python -m ahn.cli intake-status`로 DB 접수 상태를 읽는다. 공격·비용 우려가 생기면 `python -m ahn.cli pause-intake`로 새 제출을 중지한다. `resume-intake`는 원인 확인 뒤에만 실행한다. 공개만 중지할 때는 `pause-publication`; `publication-status`로 확인하고 점검 후 `resume-publication`한다. 일시 중지 동안 수동 `publish-observation`도 거부된다. 긴급 시 Render의 `AHN_REPORTING_ENABLED=0`으로 재배포하면 공개 쓰기 경로 자체를 닫을 수 있으며 기존 철회 토큰은 계속 사용할 수 있다.

## 현재 한계

- 자동 **진위 판정**, 자동 삭제 일정, 실제 동의 증명, 백업 복구 리허설은 아직 없다. 공개 조회는 최근 7일 관찰만 사용하지만 오래된 저장 행을 자동 삭제하지는 않는다. 정책 화면에 이 한계를 알리고, 철회 기능을 제공한다.
- 운영자 수동 공개·숨김은 CLI 방식이다. 개인 식별 정보가 구조화된 필드에 끼어들지 않았는지 수시로 확인해야 한다. 자동 공개된 관찰도 오류가 발견되면 숨긴다.
- Render 유료 대역폭에는 확인된 카드 청구 hard cap이 없다. 앱 제한은 과금 상한을 보장하지 않는다. 비용·트래픽 안전장치(비공개 운영 기록)를 병행한다.
- 실서비스 제보를 시험 목적으로 제출하지 않는다. 로컬 `ahn_test` DB의 발명된 값으로 접수·철회·게시·숨김을 검증한다.
