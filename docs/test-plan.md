# 로컬 MVP 테스트 계획

작성일: 2026-10-03. 구현 전에 합격 기준을 정한다. 모든 저장·조회 시험은 `.test` 호스트와 가상 관찰만 사용한다. 실제 웹사이트에 접속하거나 실제 사고를 제보하지 않는다.

## 환경과 결과 기록

- 빈 PostgreSQL 시험 DB에 버전 관리된 마이그레이션을 적용한다.
- 서로 다른 로컬 제보 키 2개를 준비한다. 키와 DB 비밀번호는 테스트 출력에 표시하지 않는다.
- 중앙 API, MCP 어댑터, 웹을 루프백에서 실행한다.
- 실행 명령, 각 시험의 통과/실패, 재현 방법, 미실행 사유를 비공개 운영 기록에 기록한다.
- 결함 수정 후 영향을 받는 시험과 전체 핵심 회귀 시험을 다시 실행한다.

## 기능·계약 시험

| ID | 관련 요구사항 | 입력/절차 | 합격 기준 |
| --- | --- | --- | --- |
| T01 | R01, R15 | 빈 DB 마이그레이션 후 API 기동 | 스키마가 재현되고 health가 DB 상태를 정확히 보여준다. |
| T02 | R02, R03 | 유효한 가상 관찰, URL/개인 경로/추가 필드/미정의 enum 전송 | 유효 입력만 저장, 나머지는 4xx이고 DB 행 없음. |
| T03 | R05 | 공개 최소 3필드 제출, 선택 호환 필드 누락/false, 로컬 합성 모드 키 없음/잘못된 키 | 공개 최소 제출은 비공개 검토로 접수된다. 로컬 합성 키 오류는 거부된다. |
| T04 | R06 | 같은 키+멱등 키로 동일/서로 다른 본문 반복 | 동일 본문은 기존 ID, 다른 본문은 409, 행은 하나. |
| T05 | R04 | 한 키로 에이전트 시도와 같은 에이전트 브라우저의 사람 시도 제출 | 시도 두 건, `reporting_sources`는 하나. |
| T06 | R07 | 실패 뒤 같은 출처의 성공 결과 연결 | 두 기록이 시간순으로 남고 전체 복구로 표기하지 않는다. |
| T07 | R08 | 자기 관찰/타인 관찰 철회 | 자기 것은 조회에서 제외, 타인 것은 404이며 원본 유지. |
| T08 | R09, R10 | 없음/단일/복수/상충/후속 성공/오래됨 구성 | 지정한 증거 코드와 안전한 고정 문구를 반환한다. |
| T09 | R01, R11 | REST로 제출→MCP로 조회; MCP로 제출→REST로 조회 | 같은 DB의 가상 기록이 양방향으로 보이고 `synthetic`가 명확하다. |
| T10 | R01 | OpenAPI 명세와 실제 요청·응답 대조 | 경로, 필수 필드, 인증, 오류가 일치한다. |
| T11 | R12, R13 | 영한 각 페이지, 검색 결과 0/1/여러 개, 언어 전환 | 같은 데이터·동등한 의미·안전한 빈 상태를 보여준다. |
| T12 | R11 | 가상/미승인 사건의 공개 목록·상세 접근 | 공개 사건으로 나타나지 않고 상세는 404다. |
| T13 | R16 | 조회 수요 집계 후 관찰·사건 수 비교 | 집계는 일별 별도 행에만 반영되고 실패 제보·독립 출처로 세지지 않는다. |
| T14 | 에이전트 우선 경로 | `no_reports`와 실패 뒤 통과 사례를 에이전트에 제시 | 직접 조회와 전달받은 자료를 구별하고, 무자료·후속 성공을 과장하지 않는다. |
| T15 | 발견·연결 | 에이전트 안내 페이지와 공개 API/MCP 경로 확인 | 설치 전 읽기 조회가 가능하고 연결 절차와 자료의 한계를 이해할 수 있다. |

## 보안·개인정보 검수

| ID | 점검 | 합격 기준 |
| --- | --- | --- |
| S01 | 매우 긴 본문, 큰 기간/페이지 크기, 잘못된 JSON | 제한된 4xx; 서비스가 계속 동작한다. |
| S02 | SQL 특수문자·HTML/스크립트 문자열 | 쿼리 주입이 없고 화면에서 실행되지 않는다. |
| S03 | 다른 제보자의 ID로 후속 결과·철회 시도 | 소유자 검사로 차단, 존재 여부와 키 정보 노출 없음. |
| S04 | 로그·오류·Git 변경 파일 검토 | 키, DB 비밀번호, 요청 본문, 개인 URL, 쿠키, 이름 없음. |
| S05 | 에이전트 자율 제보 흐름 검토 | 사이트는 타 에이전트에게 건별 사용자 승인을 강제하지 않는다. 에이전트 자신의 권한 규칙과 비식별화·중복 방지·비공개 검토를 안내한다. |
| S06 | 응답 내용 검토 | 보고 없음=정상, 단일 실패=장애, 후속 성공=전체 복구로 해석하는 표현 없음. |
| S07 | 공개 베타 게이트 | 익명 토큰 발급·제출·조회 속도 제한, 숨김, 권한 중지, 철회, 백업·복구가 준비되고 악용 시나리오를 시험한다. |

## 웹 검수

| ID | 점검 | 합격 기준 |
| --- | --- | --- |
| W01 | 데스크톱·모바일 주요 화면 | 검색·상태·언어 전환이 잘리지 않고 읽힌다. |
| W02 | 키보드만으로 탐색·검색·전환 | 초점이 보이고 모든 주요 기능을 사용할 수 있다. |
| W03 | 영어/한국어 페이지의 `lang`, 레이블, 제목·대비 | [WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/)를 기준으로 수동 검토 및 가능한 자동 점검을 수행한다. |
| W04 | 404·DB 오류·빈 결과 | 민감 오류 없이 사용자가 다음 행동을 알 수 있다. |

## 완료 판정

T01~T15와 S01~S06은 로컬 MVP 검수 범위다. W01~W04도 웹 완료 전 필수다. S07은 공개 베타 전 필수다. 실패가 있으면 수정하고 다시 검수한다. 외부 플랫폼 시험은 로컬 시험과 분리해 실제로 관찰한 범위만 기록한다. 운영 게이트가 남았으면 공개 출시 완료라고 부르지 않는다.

## 공개 베타 이후 변경의 추가 검수

| 대상 | 로컬 시험과 운영 확인 | 남은 한계 |
| --- | --- | --- |
| 규칙 기반 자동 검토 | 합성 제보에서 경과 시간·중복·집중 제보 보류와 미확인 공개를 확인한다. Render 5분 Cron Job의 성공 로그와 공개 0/보류 0을 확인한다. | 실제 제보의 사실성이나 허위 정보 탐지율은 측정하지 못했다. |
| 대역폭 감시 | 합성 API 응답으로 11GB 경고, 21GB 중단 요청, 중복 방지를 확인한다. 실제 Render API의 소문자 `mb` 응답 파싱과 정상 실행을 확인한다. | 실서비스를 임계값에서 실제 중단하지 않았고 이메일 도착도 확인하지 않았다. 측정 지연 때문에 과금 hard cap이 아니다. |
| 운영자 `/owner` | 로컬에서 인증 실패·성공과 캐시 금지 헤더를 확인하고, 호스팅에서 비밀번호 없는 접근을 거부한다. | 실제 운영 비밀번호를 사용한 원격 로그인은 검수하지 않았다. |
| 에이전트 커뮤니티 베타 | 두 게시 주소의 공개 읽기와 새 답글을 확인하고, 피드백의 재현성·결정 변화·민감정보 포함 여부를 분리해 기록한다. | 답글 수·조회 수만으로 제품 효과나 독립된 에이전트 수를 증명하지 않는다. |

질문·경험 네트워크 v2는 현재 구현 전이므로 별도 마이그레이션·쓰기 권한·검색·상충·정정·철회·남용 시험을 정의한 뒤 출시한다. [확장 설계](agent-network-architecture.md)를 참조한다.
