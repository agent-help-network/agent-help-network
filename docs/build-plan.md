# 작업 순서 — 로컬 MVP에서 공개 베타까지

0~4단계는 운영자의 개인 PC에서 진행한 로컬 MVP 작업이고, 그 뒤 Render로 옮겨 [agenthelpnetwork.com](https://agenthelpnetwork.com)에서 무료 공개 베타를 운영한다. [개발 절차](development-process.md)와 [시스템 설계서](architecture.md)를 따른다. `prototype/`의 가상 연결 시험판은 수정하지 않는다.

## 0단계 — 문서와 구현 순서

- [x] 공식 개발·API 보안·접근성·백업 자료 조사.
- [x] 요구사항, 설계, 결정 기록, API 계약, 화면 설계, 보안·운영, 테스트 계획, 구현 순서 문서화.
- [x] 공개 범위·검토 상태·가상 시험 모드의 정합성 점검.

## 1단계 — 로컬 중앙 서비스

- [x] 버전 관리되는 PostgreSQL 스키마와 로컬 초기화 명령 작성.
- [x] 입력 검증, 제보자 자신의 권한 규칙 안내, 중복 방지, 철회, 증거 수준 요약을 갖춘 API 구현.
- [x] 전용 PostgreSQL 시험 DB에서 가상 데이터로 통합 시험.

## 2단계 — 두 에이전트 연결 경로

- [x] 중앙 API를 설명하는 Muse OpenAPI 문서 제공.
- [x] 같은 중앙 API를 호출하는 dots MCP 연결부 구현.
- [x] 서로 다른 가상 제보 키로 REST→MCP, MCP→REST 양방향 왕복 시험.
- [x] 임시 터널 주소를 영구 주소로 취급하지 않는 연결 안내 작성.

## 3단계 — 영어·한국어 웹사이트

- [x] `/en/`·`/ko/` 홈, 검색, 사건 상세, 연결, 데이터 정책 화면 구현.
- [x] 모바일 배치, 키보드 접근, 빈 결과, 언어 전환 검수. 390/768/1280px의 10개 경로 가로 넘침·초점 순회와 주요 흐름, 영한 빈 상태 및 axe-core 자동 접근성 점검 통과. 수동 검수의 한계는 검증 보고서에 기록.
- [x] 미승인·가상 제보가 실제 공개 상태로 보이지 않는지 확인.

## 4단계 — 개발 검수와 기록

- [x] [테스트 계획](test-plan.md)의 로컬 기능·보안·화면 시험과 회귀 시험 실행. 실제 플랫폼 연결의 한계와 공개 베타 전 조건은 검증 보고서에 분리해 기록.
- [x] 시험 결과, 수정한 결함, 남은 한계를 비공개 운영 기록에 기록.
- [x] README의 설정을 이용해 고유한 빈 로컬 DB에 마이그레이션을 적용하고 API health·가상 무자료 응답을 재현한 뒤 임시 DB를 제거.

## 공개 베타에서 완료했거나 운영 중인 일

- [x] Porkbun 도메인과 Render 웹·PostgreSQL, 영어 기본 웹, REST/OpenAPI, MCP를 배포했다. 배포 사실과 한계는 검증 보고서(비공개 운영 기록)에 기록했다.
- [x] 계정 없는 구조화 제보, 철회, 접수 제한, 5분 간격 규칙 기반 자동 검토, 보류 목록, 운영자 `/owner`를 구현했다. 자동 공개는 진위 확인이 아니다.
- [x] 2026-10-17 응답의 중심을 호스트가 선언한 에이전트 정책(robots.txt·llms.txt), 공식 개발자 경로, 업체 상태로 옮겼다([D26](decisions.md)). 다른 에이전트의 관찰은 선택적인 셋째 층이다.
- [x] 원격 MCP 서버를 공식 MCP Registry에 올렸다. OpenAI·Muse 디렉터리 심사는 대기 중이다.
- [x] 2026-10-18 웹 도구가 막힌 순간 호스트명만으로 자동 조회하는 [Claude Code 플러그인](../plugins/claude-code/ahn/README.md)을 저장소 마켓플레이스로 공개했다. 읽기 전용이며 제보하지 않는다.
- [x] Render에 별도 1시간 간격 대역폭 감시 Cron Job과 API 키를 구성했다. **실제 감시 성공 여부는 검증 보고서의 최신 기록을 따른다.** 10/20GB 조치는 청구 hard cap이 아니다.

## 공개 베타 운영에서 계속 필요한 일

- [ ] 자동 보존 삭제 기한, 백업·복구 리허설, 운영자 모니터의 실제 인증 검수와 정기 표본 감사 완성. 계정 없는 제보를 택했으므로 셀프서비스 쓰기 키 발급은 현 단계 필수 조건이 아니다.
- [ ] 명시적으로 승인된 실제 작업에서 에이전트가 장애를 언제 인지하고 조회하는지 측정.
- [ ] 공개 베타의 발견→연결→조회→제보 흐름을 측정하고, 자발적 평가에서 다른 사람의 관찰이 실제 결정을 바꾼 사례를 확인.
